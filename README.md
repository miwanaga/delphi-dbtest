# FireDAC + InterBase Lite sample (Delphi 13)

VCL / Win32 sample using FireDAC and embedded InterBase 15 Lite.
The active project has no BDE, DBTables, DBF, or DBT dependency.
No InterBase server service is needed.

## Build and run

1. Open Project1.dproj in Delphi 13 and save all files.
2. Build the Win32 configuration.
3. Run `./Deploy-InterBase.ps1` in PowerShell in this directory.
4. Run Project1.exe.

The current project outputs the EXE in this directory. For another output
directory, pass `-Destination 'path-to-exe-folder'` to the deployment script.
The script copies engine DLLs, configuration, security database, international
support and the Lite license from the installed InterBase 15 redistributables:
`C:\Users\Public\Documents\Embarcadero\InterBase\redist\InterBase15`.
Override `-RedistRoot` if necessary. Existing ADMIN.IB and ibconfig are preserved.
Only IBLite15.slip is copied; the ToGo trial license is not copied.
The Microsoft Visual C++ 2022 runtime must also be installed.
This sample assumes its executable/runtime directory is writable.
For redistribution, comply with the InterBase Lite license in your installation.

First launch creates `%LOCALAPPDATA%\DBTest\sample.ib`, its schema and three
sample rows. Later launches preserve existing data and edits. The database
path is displayed in the window caption. An optional first command-line
argument selects another database file:

```powershell
.\Project1.exe 'C:\Data\DBTest\sample.ib'
```

The database and connection use UTF8. Creation is followed by reconnection
so the client charset applies before Unicode inserts. Names, addresses and
memo samples contain Japanese. All seed inserts run in one transaction.

## Data and display

DBGrid remains editable. Fields are created from actual InterBase metadata.

| Column | InterBase type |
| --- | --- |
| ID | VARCHAR(10) CHARACTER SET UTF8 |
| NAME | VARCHAR(50) CHARACTER SET UTF8 |
| ADDRESS | VARCHAR(100) CHARACTER SET UTF8 |
| NUM_VAL | NUMERIC(12,2) |
| FLOAT_VAL | FLOAT (single precision) |
| DOUBLE_VAL | DOUBLE PRECISION |
| BOOL_VAL | BOOLEAN |
| DATE_VAL | DATE |
| STAMP_VAL | TIMESTAMP |
| LONG_VAL | INTEGER |
| AUTO_VAL | INTEGER primary key; generator + BEFORE INSERT trigger |
| MEMO_VAL | BLOB SUB_TYPE TEXT CHARACTER SET UTF8 |
| BIN_VAL | BLOB SUB_TYPE 0 |
| OLE_VAL | BLOB SUB_TYPE 0; initially NULL |

These are InterBase equivalents, not the original physical DBF types.
FLOAT_VAL now has single precision. AUTO_VAL is generated by the database and
read-only in the grid. Binary data uses streams and preserves zero and FF bytes.
OLE_VAL is a generic binary BLOB; no OLE object is created or activated.

Calculated MEMO_TEXT shows up to 255 Unicode characters with line breaks
replaced by ` / `; BIN_HEX shows up to 64 bytes in hexadecimal.
These two preview columns are not stored in the database.

## Existing dBASE files

Existing sample.dbf/sample.dbt files are not opened, changed or imported.
Any Japanese text or other edits in those files remain in the originals;
the InterBase database starts with new sample data.

DbfSamples.pas has been removed from Project1. The old DbfSamples.pas and
DbfSampleCheck.dpr remain on disk for reference only. They are not used by
the application or its verification. Delphi 7 is no longer a build target.

## Verification

After saving all files in the IDE, run:

```powershell
.\Verify-InterBase.ps1
```

Use `-StudioRoot` if Delphi 13 is installed elsewhere.
The script builds InterBaseSampleCheck.dpr and tests a fresh database under
.verification. It instantiates the actual form and checks all 14 stored fields,
two previews, Japanese text, exact binary bytes, grid dataset edits, inserts
and generated IDs, and confirms that BDE was not loaded. A second process checks
persisted edits and unchanged row counts after restart. Test databases are
retained; the normal sample database is untouched.
