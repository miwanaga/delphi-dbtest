# Delphi 7 BDE / dBASE Level 7 all-types sample

Build Project1.dpr with Delphi 7. Run with BDE 5.x installed and a writable
executable directory. No InterBase or IBX is involved.

On form creation the application prepares sample.dbf beside the executable
and shows it in the existing DBGrid. The table uses Level 7 so it can contain
all 12 persistent dBASE native field types (not FoxPro-only types).

| Field | Native type/code | Size/decimals | Delphi field |
| --- | --- | --- | --- |
| ID | Character C | 10 | TStringField |
| NAME | Character C | 50 | TStringField |
| ADDRESS | Character C | 100 | TStringField |
| NUM_VAL | Numeric N | 12,2 | TFloatField |
| FLOAT_VAL | Float F | 16,4 | TFloatField |
| DOUBLE_VAL | Double O | 8 bytes | TFloatField |
| BOOL_VAL | Logical L | 1 byte | TBooleanField |
| DATE_VAL | Date D | 8 bytes | TDateField |
| STAMP_VAL | Timestamp @ | 8 bytes | TDateTimeField |
| LONG_VAL | Long I | 4 bytes | TIntegerField |
| AUTO_VAL | AutoIncrement + | 4 bytes | TAutoIncField |
| MEMO_VAL | Memo M | DBT pointer | TMemoField |
| BIN_VAL | Binary B | DBT pointer | TBlobField / ftTypedBinary |
| OLE_VAL | OLE G | DBT pointer | TBlobField / ftDBaseOle |

Reference: https://www.dbase.com/Knowledgebase/int/db7_file_fmt.htm

Creation uses BDE physical field descriptors, explicitly distinguishing N,
F and O. TFieldType alone can map multiple logical numeric types onto the
same DBF storage type. Startup also checks the actual DBF header type codes.
All 14 persistent fields are declared in the form so all columns are visible.
The dataset stays closed in the DFM to allow first startup without a DBF.

An empty table receives three sample rows. AutoIncrement is generated by
BDE; OLE_VAL is NULL because a valid OLE object requires an OLE producer.
The other fields contain sample values, including multiline memo text and
binary bytes with embedded zero and 0xFF. Memo, binary and OLE data live in
sample.dbt: keep it with sample.dbf when copying data. DBGrid shows blob
placeholders; it does not render memo contents or activate OLE objects.
There is no separate native dBASE Currency, Time-only or 64-bit integer type.

## Existing three-column samples

The original ID/NAME/ADDRESS table is upgraded on startup with exclusive
access. Active rows and their original string values are copied into a new
Level 7 table; added fields receive example values. The old table is retained
as sample_before_alltypes_<timestamp>.dbf before the new table is installed.
The backup includes any original sidecar files and deleted records; deleted
rows are not copied into the active all-types table. No existing table is
deleted. An unrecognized schema is rejected without changing it. Close other
applications using sample.dbf before upgrading.

The next startup keeps an existing all-types table and does not add more
sample rows when it is nonempty.

## Verification

Use delphi-build-server, compiler delphi-7.0, platform Win32, empty
configuration and mode build for Project1.dpr.

tests/DbfSampleCheck.dpr is a Delphi 7 console runtime check. It builds
against DbfSamples.pas and requires BDE at runtime. It verifies all native
field codes, scalar and blob values, restart without duplicate rows, and
upgrade of a three-column table with the original data preserved in a backup.
Run it on the Delphi 7 / BDE machine. It prints its unique temporary directory
and leaves the test files there for inspection. A successful compile does not
by itself verify BDE runtime behavior.
